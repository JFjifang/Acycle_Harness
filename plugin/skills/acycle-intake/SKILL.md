---
name: acycle-intake
description: Establish a cyclostratigraphic dataset, coordinate units, scientific question and available MATLAB/Acycle backend before analysis.
---

Use `acycle_capabilities` to check the configured backend. When the user supplies a Harness file attachment and the tool list exposes `acycle_import_attachment`, call it to obtain the workspace `input_path`. A single file in the latest attached user message can be imported without arguments; with multiple files, select an `attachment_id` from the returned candidates according to the user's request. Do not search another session's attachments or guess a storage path. When that Harness-only tool is unavailable (for example through MCP), use a file already in the current workspace. Run `acycle_inspect` on the resolved path. Distinguish a depth series from an age series, identify the proxy and units, and preserve the original file. Establish whether the user wants exploratory periodicity, a specified hypothesis, or a chronology. Infer metadata from an accompanying paper or table before asking for missing information.

Numerical processing and plots must run in MATLAB. Python is for Harness integration, transport and metadata; never silently switch to a Python analytical fallback when MATLAB is missing. Report an unavailable backend precisely and keep the request ready to rerun.

The inspect result is structural: `logical_line_count` counts CR, CRLF and LF consistently, and is not a validated sample count. Original Acycle/MATLAB reads all three newline formats. A CR-only file is not a one-row dataset; do not reinterpret it with `wc -l` or normalize it into an unnecessary LF copy. Keep the imported exact bytes and hash. Use the preview for column meaning only. Do not calculate spacing, min/max, means, trends, spectrum statistics, missing-value counts or other routine numerical QA with Python, awk or shell arithmetic; normal Acycle scientific checks belong in MATLAB and appear in the completed result. User-authorized extensions for features genuinely absent from Acycle remain allowed, with their provenance stated and a MATLAB bridge preferred.

For a sedimentation-rate plot, rate history, age model or chronology request, first establish coordinate units and the appropriate supplied chronological basis. COCO/eCOCO inference requires an explicit age/astronomical target and the scientific basis of its rate-search range; conversion using a user-provided rate or age-depth controls instead uses those supplied constraints. If a required assumption is absent from supplied metadata, ask a concise question before launching any scientific analysis. Do not label metres as "assumed", infer an age from a filename, or run mini-robot/SWA as a substitute while those requirements are missing. Attachment import and structural inspection may proceed; an unrequested preliminary spectrum does not resolve missing geological constraints.

Use the first two numeric columns only when their meaning is clear. Check duplicate coordinates, missing observations, sorting, irregular sampling and large gaps in the MATLAB result. Duplicate handling and interpolation change the effective dataset and must be visible in the report. Do not turn depth wavelengths into kyr without a stated rate or age-depth model.

Choose the operation from the scientific question and sampling, without making the user supply tool names or JSON. `acycle_analyze` provides a first exploratory mini-robot spectrum/evolution workflow. For a request about false discoveries across a spectrum, consider the SWA skill and its sampling constraints. For explicitly constrained sedimentation-rate or evolutionary-rate testing, use the COCO/eCOCO skill; geological age/targets and a justified rate range cannot be invented from the proxy alone. Use a descriptive label and record the returned run ID, effective parameters, MATLAB/Acycle provenance and artifacts. If the requested feature is outside the bridged subset, say so and prefer a small MATLAB adapter to the installed Acycle routines.

In follow-up conversation, use `acycle_rerun` or `acycle_sensitivity` on the selected saved run. Preserve its analysis operation and untouched parameters; a request to change plot range, span, window or simulation count does not itself request a different method. Use the steering skill for branching and comparison.

Return a concise dataset summary, important assumptions, available analysis path, and the next scientific decision. Do not imply that basic file inspection constitutes numerical quality control or that a successful API call means an analysis succeeded.

If the configured MATLAB/GitHub backend fails, retain and report the failed run ID, saved diagnostics and precise failure. Do not invoke `gh auth`, replace credentials, change the backend, retry the computation, or recreate it with Python on your own. The user can decide when the environment is ready for another attempt; a backend error is not a request to alter scientific data or methods.
